# Backup & Restore Guide

The app provides an application-level **JSON backup** (via Admin → Backup), and you can
also back up at the **database** level with Postgres tooling. Use both for safety.

## Application JSON backup — `/admin/backup`

- **Export** produces a JSON envelope of selected content (e.g. settings/content tables).
  A download is available via the backup page / download route.
- **Preview import** validates an uploaded JSON and reports, per table, how many rows would
  be added, already exist, or are invalid — without writing anything.
- **Apply import** writes the previewed rows.

This is convenient for migrating site settings/content between instances. It is **not** a
full database dump (it covers the content the backup service is scoped to), so pair it with
a database backup below for disaster recovery.

## Full database backup (recommended for DR)

With the Docker Compose stack:

```bash
# Dump the whole database to a file on the host
docker compose exec -T postgres pg_dump -U dbd -d dbd > backup-$(date +%F).sql

# Restore into a running, empty database
cat backup-YYYY-MM-DD.sql | docker compose exec -T postgres psql -U dbd -d dbd
```

For a clean restore, recreate the database first (or start from an empty `pgdata` volume),
then apply the dump, then `docker compose up -d` so the app runs migrations if needed
(migrations are idempotent).

## Imported icons

Icons live in the `assets` named volume (`/app/public/assets`) and the source packs under
`./data/assets` on the host. Back up `./data/assets` by copying the folder; the served
icons can be regenerated by re-running `import:assets` for each pack if needed.

## Restore checklist

1. Stop the app (`docker compose down`, **without** `-v`).
2. Restore the database dump (above).
3. Restore `./data/assets` if you keep source packs there.
4. `docker compose up -d --build`; check `docker compose logs -f app`.
5. Verify login, a few pages, and (if icons were involved) run `pnpm diagnose:assets`.

> `docker compose down -v` deletes the `pgdata` and `assets` volumes (all data and icons).
> Never use `-v` unless you intend to wipe, and only after you have a backup.
